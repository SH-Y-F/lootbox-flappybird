# 主试操作指南 · Experimenter Quick Start

> 中文版操作手册。English speakers: see the root [README](../../README.md) and each program's `README.md`.

---

## 一、实验前准备（每台机器一次）

1. 确认机器已安装 **Qt 5.15.2 (MinGW 8.1 32-bit)** 或更高版本；
2. 编译好四个程序（或用已发布的版本），得到四个 `FlappyBird.exe`；
3. 把每个 exe 放在**独立目录**中，并确保运行时能找到 Qt DLL：
   - 简单做法：把 `Qt\5.15.x\mingw81_32\bin` 加入系统 `PATH`；
   - 稳妥做法：对每个 exe 执行一次 `windeployqt FlappyBird.exe`，生成自带依赖的目录。

## 二、四个程序分别对应哪一组

| 程序目录 | 组别 | 关键视觉特征 |
|---|---|---|
| `E1-Fixed-Reward.exe` | 实验一 · 奖励固定组 | 抽奖**永远是同一只小熊** |
| `E1-Random-Reward.exe` | 实验一 · 奖励随机组 | 每次抽到的小熊**样式都不同** |
| `E2-Low-Value-Rare.exe` | 实验二 · 稀有价值相对低组 | 奖池说明写"**0.5元现金**"，金框小熊为稀有卡 |
| `E2-High-Value-Rare.exe` | 实验二 · 稀有价值相对高组 | 奖池说明写"**三元现金**"，金框小熊为稀有卡 |

> ⚠️ 四个 exe 的文件名默认都是 `FlappyBird.exe`。**强烈建议**重命名为上表的名字
> （或按 `组别_被试编号` 命名），否则极易把组别搞混、污染数据。

> 📹 **想给仓库补一段操作演示？** 四段演示位已经预留在根 README 的《实验演示 Demo》一节，
> 录屏要求、每个条件必须体现的画面、以及替换方式（覆盖 `docs/demo/` 下的同名 gif）都写在那里。

## 三、单个被试的完整流程

| 步骤 | 操作 | 说明 |
|---|---|---|
| 1 | 打开**该被试所属组别**的程序 | 组别由事先的分组名单决定 |
| 2 | 被试在开始界面输入自己的编号 | 编号用于与问卷对应 |
| 3 | 阅读指导语后点"开始游戏" | 指导语会说明"每通过 3 个管道获得一次抽奖机会" |
| 4 | 玩 Flappy Bird 攒抽奖机会 | 每通过 3 个管道 = 1 次抽奖机会 |
| 5 | 在商店点"抽奖" | 每次抽完会弹出 1–7 点"想要"程度评分框 |
| 6 | 被试可自行决定何时结束 | 强调"可以按自己的意愿结束" |
| 7 | 点击结束实验按钮 | 程序弹出"实验结束，感谢您的配合！"并写入数据 |
| 8 | **立即把 `testee.txt` 另存**到 `编号.txt` | 否则下一名被试的数据会追加到同一文件后面 |
| 9 | 让被试填写后测问卷 | 游戏成瘾量表、宝箱风险量表、loot box 游戏动机问卷等 |

## 四、数据收集与整理

程序在被试结束时会**追加**一行到运行目录的 `testee.txt`：

```text
TOTALSCORE:12,  CJNUM:9
```

- `TOTALSCORE`：得分（程序内为分数 ÷ 2）
- `CJNUM`：抽奖次数

**推荐做法**：为每名被试单独建目录运行，结束后把 `testee.txt` 重命名为
`<被试编号>.txt`，再统一汇总。汇总与字段说明见 [DATA_FORMAT.md](../DATA_FORMAT.md)。

另外，被试在抽奖后填写的 1–7 点"想要"评分**不会**自动保存，
原实验由主试记录；如需程序化采集，见 [DATA_FORMAT.md](../DATA_FORMAT.md) 第 3 节。

## 五、常见问题

| 现象 | 原因与处理 |
|---|---|
| 双击 exe 报缺少 `Qt5Core.dll` / `Qt5Multimedia.dll` | 未部署 Qt 运行库，见"实验前准备"第 3 步 |
| 程序无声音 | 检查系统音频设备；程序依赖 `multimedia` 模块与 `sounds/` 资源 |
| 抽奖按钮感觉"没反应" | 固定组有 3.5 秒防连点（见 [MODIFICATIONS.md](../MODIFICATIONS.md)） |
| 抽奖次数显示与预期不符 | 商店页显示的是**总得分 / 抽奖次数**换算值，以 `testee.txt` 的 `CJNUM` 为准 |
| 抽到很多次仍没有稀有卡 | 稀有卡为随机事件，属正常现象 |

## 六、数据安全

- **切勿**把包含真实被试数据的 `testee.txt` 提交到 GitHub（仓库 `.gitignore` 已做忽略，
  但仍请在 `git add` 前用 `git status` 复查）；
- 问卷数据与行为数据应分开存放，并按伦理审查要求脱敏、限期保存。
